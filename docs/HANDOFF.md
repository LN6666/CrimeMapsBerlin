# Handoff and owner decisions

## Current objective

CrimeMapsBerlin replaces CiviFlux. The owner authorized removal of the former plugin code locally and on GitHub, and renaming the repository. Git history is preserved. The old traffic disruption, digital twin, ontology/PPR and Qwen development plans are superseded for this product.

## Requirements retained from conversation

1. Public GitHub repository in the owner's LN6666 account; version control, usable documentation and cross-account handoff.
2. Software engineering: modular boundaries, small explicit contracts, reproducible source processing, focused tests, honest CI and maintainable code.
3. Berlin map matching the observable England/Wales reference behavior: year/month, two hex scales, zoom/click stats. Do not claim unknown reference internals are identical.
4. Europe-wide police source research for relevant POI categories, category colors, 50 m circles for small places, actual station areas, nearby mention darkening and Berlin kbO.
5. Fetch missing announcements directly from police, not just an intermediary feed.
6. Browser performance: staged/month/viewport loading, bounded caches, no thousands of DOM markers.
7. Continuous source acquisition via deterministic crawlers. The LLM must read every original announcement before semantic exclusion, case splitting or scene selection; fixed rules may propose candidates and then validate evidence, source versions and geometry, but cannot decide omission or publication. The owner inspects and questions the review results as in the earlier Berlin work. Missing, stale or uncertain review or owner approval blocks new publication. No paid API or local Qwen deployment has been authorized.
8. Preserve every source-backed incident, accident, discovery, operation, arrest, search, background and unresolved scene. At most one reviewed incident/accident point per announcement enters hex counts; secondary points, areas, district polygons and road ranges remain visible without an extra count. Never silently call an announcement one offence.
9. Fourteen selected cities appear in this order: Berlin, Hamburg, Munich, Cologne, Frankfurt am Main; Düsseldorf, Stuttgart, Leipzig, Dortmund, Bremen; Essen, Dresden, Hannover, Nuremberg. Use three repositories grouped 5/5/4, with Berlin as the default entrance and obvious city switching. Only the existing Berlin repository and Berlin map are live; pending choices must not imply other maps exist.

Repository naming for the agreed split: keep the existing `CrimeMapsBerlin` as the default entrance and first five-city repository; [CrimeMapsDE-Cities-06-10](https://github.com/LN6666/CrimeMapsDE-Cities-06-10) holds Düsseldorf, Stuttgart, Leipzig, Dortmund and Bremen; [CrimeMapsDE-Cities-11-14](https://github.com/LN6666/CrimeMapsDE-Cities-11-14) holds Essen, Dresden, Hannover and Nuremberg. The stable `CrimeMapsDE-Cities-XX-YY` names encode the selected order without implying that every city map is already complete. Their descriptions and READMEs list exact cities, sources and the current unpublished state. Use stable lowercase city slugs in code and data paths, a source ID plus revision hash for local records, and a city-scoped versioned generation for any approved public data. Raw bodies, source downloads, local review ledgers and unapproved derived datasets do not receive release names or enter Git. The new repositories currently contain code and synthetic tests only; their intake adapters are separated from the Berlin repository.

Nearby darkening defaults to **same mentioned type**, pending any owner change. The question was offered but no answer arrived; this avoids unrelated nearby businesses receiving identical highlighting.

`reviewed_scenes.py` is the fail-closed handoff from the imported source-first LLM ledger to GIS work. It revalidates each current source and decision hash, preserves every reviewed incident and formal location, and emits explicit checked-point, road, area, district or unresolved geometry tasks. Every task now carries its source URL, verbatim location evidence, semantic decision hash and a separate geometry-request hash. `city_geometry_index.py` builds the other half of that handoff from the checked Geofabrik PBF: all named objects, roads, addresses and administrative areas are clipped to the selected municipality and retain stable OSM IDs and exact geometry hashes. It deliberately performs no police-text-to-OSM match. `geometry_decisions.py` then accepts only an explicit LLM selection, binds each row to the current request hash and checked OSM-index digest, checks geometry type and city containment, and derives output from the selected source objects. `map_decisions.py` adds the final source-backed LLM choices needed by the browser: a category for every reviewed incident and zero or one linked in-city incident/accident location that may count for the announcement. `reviewed_city_map.py` validates those exact decisions and assembles an ignored browser candidate containing all points, roads, areas, districts and unresolved scenes, with no inferred POI association. Its notification policy is `failed_runs_only`; meaningful findings remain in the task record without routine window notifications.
