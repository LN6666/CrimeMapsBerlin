# Handoff and owner decisions

## Current objective

CrimeMapsBerlin replaces CiviFlux. The owner authorized removal of the former plugin code locally and on GitHub, and renaming the repository. Git history is preserved. The old traffic disruption, digital twin, ontology/PPR and Qwen development plans are superseded for this product.

## Requirements retained from conversation

1. Public GitHub repository in the owner's LN6666 account; version control, usable documentation and cross-account handoff.
2. Software engineering: modular boundaries, small explicit contracts, reproducible source processing, focused tests, honest CI and maintainable code.
3. Berlin map matching the observable England/Wales reference behavior: year/month, two hex scales, zoom/click stats. Do not claim unknown reference internals are identical.
4. Europe-wide police source research for relevant POI categories, category colors, 50 m circles for small places, actual station areas, nearby mention darkening and Berlin kbO.
5. Fetch missing announcements directly from police, not just an intermediary feed.
6. Browser performance: staged/month/viewport loading, bounded caches, no thousands of DOM markers.
7. Continuous source acquisition via deterministic crawlers. The LLM must read every original announcement before semantic exclusion, case splitting or scene selection; fixed rules may propose candidates and then validate evidence, source versions and geometry, but cannot decide omission or publication. The owner inspects and questions the review results as in the earlier Berlin work. Missing, stale or uncertain review or owner approval blocks new publication. No paid API or local Qwen deployment has been authorized.
8. Preserve every source-backed incident, accident, discovery, operation, arrest, search, background and unresolved scene. At most one reviewed incident/accident point per announcement enters hex counts; secondary points, areas, district polygons and road ranges remain visible without an extra count. Never silently call an announcement one offence.
9. Fourteen selected cities appear in this order: Berlin, Hamburg, Munich, Cologne, Frankfurt am Main; Düsseldorf, Stuttgart, Leipzig, Dortmund, Bremen; Essen, Dresden, Hannover, Nuremberg. Use three repositories grouped 5/5/4, with Berlin as the default entrance and obvious city switching. Only the existing Berlin repository and Berlin map are live; pending choices must not imply other maps exist.

Repository naming for the agreed split: keep the existing `CrimeMapsBerlin` as the default entrance and first five-city repository; [CrimeMapsDE-Cities-06-10](https://github.com/LN6666/CrimeMapsDE-Cities-06-10) holds Düsseldorf, Stuttgart, Leipzig, Dortmund and Bremen; [CrimeMapsDE-Cities-11-14](https://github.com/LN6666/CrimeMapsDE-Cities-11-14) holds Essen, Dresden, Hannover and Nuremberg. The stable `CrimeMapsDE-Cities-XX-YY` names encode the selected order without implying that every city map is already complete. Their descriptions and READMEs list exact cities, sources and the current unpublished state. Use stable lowercase city slugs in code and data paths, a source ID plus revision hash for local records, and a city-scoped versioned generation for any approved public data. Raw bodies, source downloads, local review ledgers and unapproved derived datasets do not receive release names or enter Git. The new repositories currently contain code and synthetic tests only; their intake adapters are separated from the Berlin repository.

Nearby darkening defaults to **same mentioned type**, pending any owner change. The question was offered but no answer arrived; this avoids unrelated nearby businesses receiving identical highlighting.

## First steps for another maintainer/account

Read README → ARCHITECTURE → UPDATES → DATA. Run `git status`, check current branch and the migration PR, then run the focused test commands in README. Local ignored data is not available on another computer: run the documented download/import commands. A new GitHub account needs repository permissions for push, but no API subscription is needed for local development.

Source registry coverage and kbO vector completion remain open tasks. Geocoding is deliberately conservative and needs audited improvements before a claim of comprehensive incident mapping. The runtime build audit contains the current counts; do not freeze a partially imported count as permanent product status.

Geocoding v2 addresses the owner's observed omissions: full narrative scanning, German variants/abbreviations, parks/stations/venues, OSM locality clipping, explicit addresses and nearby fragment clustering. Every rebuild reruns these rules over all stored reports. Review reasons distinguish non-incident notices, district-only information, spelling suggestions, unscoped/multiple locations, disconnected/wide geometries and locality conflicts. There is no completed human correction interface; do not claim these remaining queues resolve themselves. See DATA for the actual heuristics and `scripts/safety/audit_geocodes.py` for a same-source comparison.

Rule version 3 adds incident-scene priority, action-linked temporal clauses, compact 2–4-road junctions, and explicitly bounded street sections. Public scene-selection/additional-candidate fields and selected section lines are implemented; missing or moving scenes still need review. The frozen v2→v3 comparison lives locally in `.runtime/safety/scene-priority/`; regression fixtures remain synthetic. DATA records actual counts and tolerances. Continue to distinguish crime traces on fixed objects from merely finding an injured person.

Rule version 4 adds station/genitive context, ordinary-word disambiguation, adjacent junction anchors, explicit origin/destination roles, fixed-fire evidence and scene-consistent locality context. The frozen v3→v4 comparison in `.runtime/safety/context-v4/` maps 746/1,098 announcements (66 gained, 14 withdrawn; 352 unresolved), using unchanged bodies/indexes. This is mapping coverage, not accuracy. All runtime evidence stays local and is unavailable on a fresh computer; synthetic regression fixtures remain in Git.

Rule version 5 adds singular official `Tatort:`, `Unfallort:` and fixed-scene `Ort:` headings as geometry candidates, accepts an unambiguous Hamburg neighbourhood heading for geographic clipping, and keeps missing-person searches and administrative notices available for semantic review. Hamburg uses EPSG:25832; Berlin remains EPSG:25833. A local same-source v4→v5 comparison on 1,100 Berlin articles found 747 mapped before and after, with no gained, lost or moved points. Six aggregate-bulletin methods changed from `non_incident_report` to `multi_event_summary`, without creating points. The local evidence is in `.runtime/safety/geo-v5/`.

Hamburg's current official newsroom scan is complete for the requested 2026 window: **485/485 discovered announcements have current bodies, with no fetch/parser backlog**. After source-backed review corrections, 113 ordinary announcements retain a top-level count point. The 27 plural-location announcements are now controlled by local LLM decisions rather than the rule parser: 105 distinct scenes comprise 6 points, 27 road ranges, 4 named areas, 30 district-only geometries and 38 scenes without display geometry. Three of those announcements have a reviewed primary point, bringing the current announcement-level point total to **116**. One contemporaneous location pair is explicitly marked as having an unresolved relationship instead of being forced into the same case. `scene-decisions.json` is source-hash and evidence bound, ignored by Git and mandatory for these reports; the automatic 133-scene draft remains only a diagnostic candidate. Counts describe local extraction coverage, not accuracy or a published Hamburg map.

The owner also requested a familiar street/imagery map. `web/src/safety/basemaps.ts` owns standard OSM tiles, Berlin government 2026 aerial WMS and local simplified roads. Basemap switching preserves analytical state and cancels inactive sources; failed external tiles stop and fall back visibly. No API key/subscription is required. The aerial layer is not satellite/live imagery. See DATA for sources, licence, flight date and display-only use.

The owner requested visible road ranges for reports whose source gives a road but no defensible point. Legacy single-scene reports can carry top-level `candidate_road_geometry`; multi-scene reports carry the geometry on each reviewed scene. Both are additive display fields. The batched dashed-road layer and card focus action use the existing monthly loading/filtering path. Do not count these ranges as point-located reports, assign a midpoint to a hex or darken every nearby POI along a road. Other review reasons such as conflicting locality, travel origin or spelling suggestions do not automatically receive road geometry.

## Git workflow

Use `codex/` feature branches and pull requests for subsequent changes. Check Python tests, TypeScript/build and browser tests. Do not disable failing checks or erase Git history. Main's reviewer requirements remain in force; completing code and passing CI is distinct from an approved merge. The two additional repositories were initialized with their own source intake code and synthetic tests. The Berlin/Hamburg/first-group changes remain on this development branch until reviewed through a pull request. No generated city data has been uploaded.

The AI review ledger and owner approval receipt are local and keyed to the current source/extraction/decision set; neither is raw-data material for Git. The Codex desktop heartbeat `crimemapsberlin` continues bounded source-backed review every three days at 21:30 in the machine's local time zone (currently Asia/Tokyo), prioritizing Hamburg and then other cities whose official source entry is verified. Its notification policy is `failed_runs_only`; meaningful findings remain in the task record without routine window notifications. It must not approve its own packet, push directly to protected `main`, claim its own verdict proves location accuracy, or silently publish before the owner has inspected and questioned the results. No browser-model backend or paid API is installed. The existing Berlin map predates the new review gate and remains the last good snapshot while the initial backlog is examined.
