# CrimeMaps security model

Reviewed on 2026-10-03. This is an implementation candidate. Integration, repository settings and real service configuration are separate acceptance steps.

The product consists of 14 independent static maps, reviewed public map JSON and assets, GitHub source/CI/Pages, optional country pageview aggregation and a private feedback Worker. Official reports, OSM data, upstream classification, translated strings and visitor input cross trust boundaries. Source truth still depends on current source/semantic/geometry review; this security gate does not perform that review.

| Boundary / threat | Current evidence and candidate control | Remaining exposure |
|---|---|---|
| Report, POI, translated text → DOM / XSS | Current cards use textContent and DOM nodes. Keep that API for announcements/feedback; HTML template is only trusted static application text. security.ts rejects active schemes, controls, userinfo and nonstandard ports. CSP permits only local executable assets and the explicit challenge host when enabled. | Translation files are executable-build input and need normal code review. CSP does not validate source facts or prevent an authorized compromised build. MapLibre needs inline CSS; no inline script or unsafe-eval is allowed. |
| Manifest → URL / traversal, exfiltration and browser exhaustion | Validate generation, YYYY-MM months, category/tile components, finite positive tile sizes and index counts. DataClient limits requests to its current local generation, rejects redirects, omits credentials/referrers; actual stream limit 64 MiB and cancellation remain. Cache weight is serialized UTF-16, not total heap. | A trusted but very large GeoJSON can still consume browser heap; performance limits and 14 integrated-browser checks remain required. |
| Static artifact → public site / unintended disclosure or mutation | artifact_gate.py rejects symlinks, runtime/review/SQLite/ZIP/PBF/source-map/credential signatures/private body fields, active SVG, unsafe HTML and multiple generations; 900,000,000 byte budget. Detached receipt binds commit, city and the exact file set/hashes. Verify against a separately trusted receipt SHA immediately before upload. | The scanner is a bounded allowlist and known-signature check, not a proof that arbitrary text contains no personal information/secrets. Semantic/redaction review remains mandatory. No runtime ZIP upload/extraction is exposed. |
| Source-review ZIP → offline local tools | Existing source_review_pack.py rejects traversal, duplicate members, symlinks and unchecked bytes; the website gate disallows ZIP entirely. | Offline review packs are private and do not belong in repository or Pages artifact. Hashes detect byte mismatch, not a malicious source. |
| Optional CSV/SVG export → spreadsheets/browser | No public CSV importer/exporter exists in the current map. Analytics SVG uses fixed elements, finite integers, escaped text and no remote references; gate validates SVG. If CSV is later added, neutralize leading =,+,-,@ and control prefixes before spreadsheet use. | JSON/CSV conversion outside the product can introduce formulas. A safe SVG rendering is not an authenticated statistic. |
| PR/dependency → CI secrets / supply chain | Existing workflow uses full commit SHA, contents:read, npm ci and uv --locked. Candidate disables checkout credential persistence, bounds job duration and supplies Dependabot/CODEOWNERS entries. Current npm audit reports 0 known advisories; current 132 tracked small files show 0 known credential signatures. | These scoped checks do not prove absence of vulnerabilities, stale transitive advisories or historical credential exposure. No self-hosted public PR runners; no pull_request_target/workflow_run executing untrusted PR artifacts with deploy secrets. |
| CI → release integrity / rollback | Build and test are read-only. Only a reviewed main commit receives a protected deployment job with pages:write and id-token:write. Keep source and artifact approval records outside public payload; verify trusted receipt digest. Retain an immutable last-good artifact and its receipt for rollback. | SHA-256 is not a deployed digital signature. No signing key/attestation trust root or anti-tamper service has been deployed here. A compromised account can replace a site. Protect owner account and repository settings; restore from independently retained accepted artifact. |
| Browser → counting / forged events and free-quota exhaustion | Analytics candidate uses opt-in UI, fixed city/path, trusted request.cf country, server-verified single-use Turnstile hostname/action/cdata, short HMAC limits, transactional admissions and 5,000/day global accepted cap. Public stats suppress groups <20 and round down to 10. | Origin/CORS is not authentication; all project paths share one GitHub origin. Challenge-solving clients can inflate accepted PV. HMAC limits, botnets and rejected requests still consume platform request/CPU/read quotas. Counts are voluntary accepted pageviews, not exact visitors. |
| Browser → feedback / public disclosure, identity and abuse | Private POST intake, no public list/update endpoint, strict schema/stream body size/plain text, parameterized SQL, server challenge validation, atomic 5/hour and daily caps. Delete capability is 256 random bits; server stores only hash. Management uses server-only separate Bearer token and JSON. 30-day application TTL plus cleanup. | Operators and the provider can access submissions. Do not ask for names/email/identifying case details. Delete tokens must stay out of URLs, logs, screenshots and public issues. Provider backups can outlive application deletion. Plain-text content must stay inert in future operator UI. |
| Service → diagnostics / secrets and personal data | Workers explicitly disable observability and omit request/response/body/token logs. HMACs rotate and expire; raw IP is neither application-stored nor passed to Siteverify. Data and optional-service requests omit credentials and referrers. Global strict-origin-when-cross-origin preserves only the site origin for OSM tile-provider policy; official outbound links remain noreferrer. | Cloudflare receives transport/device data; GitHub, OSM/GDI and challenge services also process ordinary requests. Disabling application logs does not eliminate provider security processing. |

## Privacy decisions for Germany/EU access

Aggregate country counts use trusted edge country classification; no client country, account, cookie, UV identifier or long-term fingerprint is collected. Short keyed IP hashes are pseudonymous abuse-control records. Analytics limits expire after 120 seconds; minute cleanup normally removes active-database rows within about three minutes. Feedback limit records expire at the next UTC midnight; daily 03:10 UTC cleanup normally removes them within 27 hours 10 minutes of creation. Requests also prune expired rows. Scheduling failure or quota exhaustion can delay physical cleanup and requires operator recovery. Feedback is excluded from operator reads after 30 days; requests or the daily cleanup delete expired active-database rows, so physical storage can extend to about 31 days. Capability or authorized operator deletion removes the active row immediately. Provider recovery/backup retention is separate and must be disclosed; restored databases must be pruned before service resumes. Country counts persist as rounded/suppressed public aggregates.

Do not call the design “fully anonymous”, “IP-free” or “GDPR-compliant by default”. Before collection is enabled, the actual operator must publish purpose, lawful basis, controller/contact, recipient/provider, transfer safeguards, actual retention including backups, rights and complaint route. Analytics opt-in must precede third-party challenge loading and be withdrawable without losing map access. Feedback challenge loading must have a clear notice and remain separate from optional statistics. A no-cookie implementation alone does not establish an exemption from German terminal-access rules. This is a conservative engineering interpretation of the [DSK digital-services guidance](https://www.datenschutzkonferenz-online.de/media/oh/OH_Digitale_Dienste.pdf), not an individual legal determination. GDPR principles include purpose limitation, data minimization and limited retention: [official regulation](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng/).

Provider evidence must name the actual account/plan, processing agreement and transfer safeguards. No account, contract acceptance, live keys, EU-only processing, provider log deletion or production deployment is proven by these local candidates. The [Turnstile Privacy Addendum](https://www.cloudflare.com/turnstile-privacy-policy/) describes IP, TLS fingerprint, user-agent and site-origin signals. Cloudflare acts as processor to deliver the service and as controller to improve bot detection. This second purpose must be covered in the actual notice and legal assessment; the application’s avoidance of fingerprints does not remove provider signal processing. The [Cloudflare DPA](https://www.cloudflare.com/cloudflare-customer-dpa/) defines processing/transfer terms; their applicability must be confirmed for the actual account. [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/) are enabled by default for newly created Workers, so the disabled configuration and dashboard readback are deployment requirements.

## Static hosting and limits

GitHub Pages is a static host; this candidate does not claim a configurable full WAF or prevention of denial of service. The [OSMF tile](https://operations.osmfoundation.org/policies/tiles/) and [vector](https://operations.osmfoundation.org/policies/vector/) policies require identifiable browser requests and bounded viewport usage; do not strip the tile Referer, bulk-download or bypass their caches.

Meta CSP can restrict resource loading but cannot set frame-ancestors, HSTS, Permissions-Policy or X-Content-Type-Options HTTP headers. If a reviewed reverse proxy/header-capable host is later configured, add those response headers there. Never describe a copied _headers file as effective on GitHub Pages. See [MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP) and [frame-ancestors limitations](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).

The 900 MB artifact cap leaves room below the project’s conservative 1,000,000,000-byte Pages budget. GitHub also applies soft bandwidth/build and rate limits: [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). Shared Cloudflare Free quotas still apply to attempted traffic, cleanup and all 14 cities; application caps do not guarantee availability or prevent all consumption. Account plan must remain Free and no paid upgrade is authorized. Official [Workers/D1 pricing](https://developers.cloudflare.com/workers/platform/pricing/) was checked on 2026-10-03; deployment must verify the live account limits rather than treating this document as a billing guarantee.

## Repository settings and incident handling

Migration is the only GitHub/settings/integration writer. For each of 14 repositories it must preserve existing history/protection and record default read token permission, no automatic PR approval, full-SHA Actions references, required current checks/reviews, no force push/deletion, private reporting and secret/push-protection state. Current read-only evidence is captured in the security stage; it is a point-in-time snapshot, not a promise about future settings. Private reporting must be enabled and independently read back before advertising a functioning private vulnerability endpoint. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use) and [private reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).

On a leaked credential, revoke/rotate it first; remove sensitive logs and assess access. Deleting the visible file or masking new logs does not revoke a key. Stop optional intake/counting on suspected exposure; preserve a private incident record and redeploy only accepted bytes. On corrupted data/build failure, retain or restore last-good accepted artifacts; do not silently rebuild from unreviewed sources. Notify affected parties only through the owner-authorized incident process, with statutory breach obligations evaluated for the actual incident. No external notifications were sent by this audit.

## Required integration evidence

- security.ts is wired into all manifest/data requests; month/viewport cancellation and caches pass after the three-way merge.
- Built HTML has the restrictive CSP before executable elements. API origins are exact reviewed HTTPS names; Turnstile is added only when real configuration/notice is accepted.
- artifact seal/verify pass for each single-city accepted artifact, trusted receipt SHA is outside payload, and code commit matches tested release.
- Pages job cannot execute from a PR/untrusted artifact; deploy permission is job-local; no paid services or uploaded runtime archives.
- Worker tests use actual SQLite/HTTP locally; production requires real challenge, CORS, rate/cap, retention, operator access and credential-redaction checks. Local mocks are never production evidence.
- Real controller/privacy details and provider settings are supplied, language text is integrated, and private-reporting state is read back. Until then optional services remain disabled.
